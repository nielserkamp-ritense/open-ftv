# Logius ADL Level 1 — Paragraph-Level Compliance Matrix

This walks the Logius Authorization Decision Log 1.0.0 standard's own text paragraph by paragraph, clause by clause. One row per numbered spec clause where the clause contains a single testable statement; split into multiple rows where a clause bundles several distinct MUST/SHOULD statements (e.g. §3.2.2); combined where a clause's statements are only meaningfully verified together.

Only §1–§3 are in scope: §4 and §5 are explicitly marked "This section is non-normative" in the spec itself, so nothing in them is a conformance requirement.

§3.3 (Interface) is not Level 1-specific — it's the general field vocabulary that applies across all four detail levels defined in §4.1. Three of its attributes (`adl.core.policies`, `adl.core.information`, `adl.core.configuration`) are marked "conditional" in the spec: required only when that aspect is made retrievable, which §4.1 ties to Level 2, 3, and 4 respectively. Since this implementation deliberately stops at Level 1, that condition never fires for those three — so they show up below as N/A, not as gaps.

**Verdict key**: ✅ Full (a test proves it) · 🟡 Integration-only (proven, but only by an integration test that runs in the CI pipeline) · 🔷 Depends on deployment (not application code) · ⬜ N/A (out of scope, non-mandatory, or not applicable to Level 1)

Test names in the **Test(s)** column are shown in <code style="color:#4CAF50">green</code>.

## Bottom line

Every MUST/SHOULD clause in §2–§3 that applies to a Level 1 implementation is either ✅ proven by a test, 🟡 proven but only by an integration test that needs a live Postgres and runs in the CI pipeline (inherent to what it proves, not a coverage gap), 🔷 a deployment-configuration matter outside application code, or ⬜ genuinely not applicable to this implementation's Level 1 scope (source-reference attributes, non-HTTP protocols, decision caching — none of which are used here).

No clause is left unaccounted for.
